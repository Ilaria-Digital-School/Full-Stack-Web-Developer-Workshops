# View and browse the source code of three websites you use

Theoretical Recap The foundational concept for this workshop is client-server architecture. In web development, your browser acts as the client, which requests data from a server. The server sends back files containing the website's source code: HTML for structure, CSS for styling, and JavaScript for behavior and interactivity. This code is then interpreted and rendered by your browser into the visual page you see. A clear mental model is to think of a building. The HTML provides the architectural blueprint and the raw building materials. The CSS decides the paint colors, the interior design, and the landscaping. JavaScript adds the moving components like elevators, automatic doors, and smart home systems. These three technologies combine to create the final user experience. A common mistake is assuming the source code you can view is the server-side, proprietary code. You are only seeing the front-end, client-side code sent to your browser. This means you will not see the Python, PHP, or Node.js that runs on the server, nor will you see the SQL databases. You are exploring the final output that the user's device receives, which is a crucial distinction for a full-stack developer who must understand the entire flow. As a simple numeric example, a basic web page might consist of a single HTML file of 50 lines that links to a CSS file of 30 lines and a JavaScript file of 20 lines.
