# Redo the reorganisation from the editor's terminal

Connect concepts through practice You have learned to use your code editor's graphical interface and its integrated terminal separately. This workshop bridges those tools. The terminal is a text-based interface to your operating system, allowing you to navigate folders and manipulate files using commands. Your code editor can host this terminal, letting you run commands without switching applications. A key mental model is the 'working directory' or 'current folder'. Every terminal session operates within one folder, and commands act relative to that location. You must know your location with 'pwd' and move with 'cd'. Another is the distinction between relative and absolute paths, allowing you to target folders precisely. Common mistakes include losing track of your working directory, which leads to running commands in the wrong place. Forgetting case sensitivity in Linux and macOS commands causes errors. Using relative paths when a deeper folder move makes an absolute path safer is a typical oversight. Not confirming actions before using powerful commands like 'rm' can delete unintended files. Consider reorganizing a project's 'src' folder from a terminal starting in your home directory. You would first 'cd' to the project folder, list contents with 'ls', and then use 'mv' commands to move files between directories you create with 'mkdir'. This sequential flow is what you will practice.
