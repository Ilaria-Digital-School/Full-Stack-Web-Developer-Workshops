# Rewrite ambiguous instructions so they leave no doubt

Theoretical Recap: From Ambiguity to Precision Ambiguous instructions are statements that can be interpreted in more than one way, leaving room for doubt, error, or unintended outcomes. As a developer, you must write instructions for computers that are literal and for humans who may need to execute your plans. The core mental model is simple: think in terms of inputs, precise actions, and measurable outputs, leaving no assumptions unstated. Common mistakes include using vague terms like "do something," "handle it properly," or "make it look nice." Other pitfalls are failing to specify starting conditions, not defining the expected end state, and using relative terms without reference points. Ambiguity causes failed builds, bugs, and team friction. Consider this ambiguous instruction: "Add a newsletter signup." A precise version would be: "In the website footer, below the copyright text, add a text input field with placeholder 'Enter your email' and a blue button labelled 'Subscribe'. On clicking the button, validate the input contains an '@' symbol; if valid, submit the form to the URL '/api/subscribe'." This specifies the where, what, how, and success criteria, leaving no doubt.
