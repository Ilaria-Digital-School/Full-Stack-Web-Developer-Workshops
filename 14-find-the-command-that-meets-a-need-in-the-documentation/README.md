# Find the command that meets a need in the documentation

Theoretical recap: Searching for commands efficiently Documentation is the official manual for a tool or technology. It explains how to use it, lists its features, and provides examples. A command is a specific instruction you give to a computer system or tool to perform a task. The mental model for finding commands is a targeted search, not random browsing. You start from a clear need, identify keywords, and then filter the results you find. A common mistake is to start reading documentation from the beginning like a book. This is time-consuming and often confusing. Another mistake is to use vague search terms, which yields irrelevant results. The key is to treat the documentation as a searchable reference, not a linear narrative. Consider this mini example: you are using Git, and you need to see a summary of changes before committing them. The need is "preview changes." Keywords for a web search or within Git's own help could be "Git see what you will commit" or "Git diff staged." The correct command is `git diff --cached`, which shows the differences for files you have already added to the staging area.
