# Install Git and create the repository for your working folder

Theoretical Recap Version control is essential for your work as a developer. Git is a distributed version control system that tracks changes in any set of files. It allows you to create a complete history of your work, revert to previous states, and collaborate with others. A key mental model is the repository (repo). This is a data structure storing your project's files and the complete history of changes. Think of it as a timeline where each saved state is a commit. You work locally on your machine, and changes are tracked in your local repository. A common mistake is treating Git like a simple backup tool. It is much more powerful. Another frequent error is committing changes without clear, descriptive messages, making the history hard to navigate. Beginners often forget to stage their files before committing, or they commit huge batches of unrelated changes together. A mini example: You have a folder named 'my_project' with a file 'index.html'. After editing the file, you would add ('stage') it to the staging area with the Git command. Then you commit it with a message like "Add basic HTML structure". This creates a permanent snapshot in your timeline.
