# A file organisation problem solved, from breakdown to terminal

Recap: from breakdown to command Breaking down a problem means turning one vague goal, such as "tidy this folder", into small actions you can check, such as "create a folder for invoices" or "move the 5 PDF invoices into it". The terminal does exactly what you type, from the current directory shown by pwd. It never guesses what you meant. Your mental model is that every command has a starting point (where you are), an action (mkdir, mv, cp, ls) and a target (a relative or absolute path). Git is your safety net. Each commit is a snapshot of your work that you can return to. Markdown is how you document what you did, so that someone else can understand and reproduce it. Common mistakes: • Running a command from the wrong directory. • Forgetting quotes around a name that contains spaces. The command mv meeting notes.txt notes/ is read as two separate files. • Moving or deleting files without checking with ls first. • Committing once at the very end instead of after each stage. Mini example: a folder holds 24 files, made up of 6 PDF invoices, 8 JPG photos, 7 TXT notes and 3 duplicates. Dragging them one by one takes 24 actions. With a breakdown, you create 4 subfolders in a single mkdir command. You then move each family with a wildcard pattern (the star symbol followed by the extension). That is 4 mv commands instead of 24 manual moves. You check with ls after each...
