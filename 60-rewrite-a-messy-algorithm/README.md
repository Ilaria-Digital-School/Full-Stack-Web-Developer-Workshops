# Rewrite a messy algorithm

THEORETICAL RECAP An algorithm is a finite, ordered sequence of unambiguous instructions designed to solve a specific problem. The key word here is 'ordered': each step must follow logically from the previous one, and every instruction must be clear enough that anyone — human or machine — can execute it without interpretation. In pseudo-code, you express this logic in plain structured language, independent of any programming language. The two most fundamental concepts you have already encountered are sequencing (instructions executed one after another, in order) and flow (the path execution takes from start to finish). A well-written algorithm has three non-negotiable qualities: clarity (each step is unambiguous), granularity (steps are broken down to the right level of detail — neither too vague nor unnecessarily fragmented), and linearity (the execution flow is easy to follow without backtracking or confusion). Common mistakes beginners make include: mixing the order of steps, skipping implicit but necessary actions, using ambiguous verbs ('handle', 'process', 'deal with'), writing steps that are too broad to be actionable, and failing to define a clear start and end point. A simple mental model: think of your algorithm as a recipe handed to someone who has never cooked before. If a step can be misunderstood or skipped without the reader noticing, it needs to be rewritten. Mini example of a messy instruction: 'Get the data and do stuff with it then show results.'
