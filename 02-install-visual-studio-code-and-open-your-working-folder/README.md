# Install Visual Studio Code and open your working folder

Recap: Files, paths, and code editors In previous activities, you learned how the computer stores your work in files organized within folders. You explored how file extensions identify a file's type and purpose, and you created your working directory's folder structure. A fundamental mental model for a developer is that a project is a collection of files and folders at a specific location, or path, on your computer. A path is the sequence of folders you navigate to reach a file, like a precise address. A common mistake is misunderstanding the difference between a file's location and its content, or confusing local paths on your machine with the paths a web server might use. Another error is not organizing your workspace from the start, leading to messy projects. For example, your working directory 'my_projects' might have subfolders like 'week_1' and 'week_2'. The full path to 'week_1' could be 'C:/Users/YourName/Documents/my_projects/week_1'. This path is what a code editor needs to correctly load and manage your project files. A code editor, unlike a simple word processor, is software designed for writing and managing code. It provides features like syntax highlighting, auto-completion, and integrated file browsing, which are essential for efficient development. The goal is to link this tool directly to your file system, allowing you to work on the precise project folder you have already set up.
