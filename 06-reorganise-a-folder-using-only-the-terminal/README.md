# Reorganise a folder using only the terminal

Theory Recap: The Filesystem and Terminal Commands You have been navigating your computer using a graphical user interface (GUI) for years. As a developer, you must also master the command-line interface (CLI), which provides direct, powerful control over your operating system's filesystem. The filesystem is a hierarchical tree structure of directories (folders) and files. Each item has a path, which is its address starting from the root `/` on Linux/macOS or a drive letter like `C:\` on Windows. The terminal, or shell, is your text-based gateway to this structure. Core commands you have learned, like `pwd`, `ls`, `cd`, `mkdir`, `cp`, `mv`, and `rm`, are your fundamental tools. A clear mental model is crucial: you are always operating from a 'current working directory'. Commands affect files relative to this location unless you specify an absolute path. A common beginner mistake is misinterpreting paths, leading to commands failing or, worse, deleting the wrong files. Another is forgetting that `mv` serves both to 'move' and to 'rename' items. Use `ls` frequently to confirm your location and the items present. For example, to create a file named `note.txt` inside a subfolder `docs`, you would first ensure you are in the correct parent directory, then run `mkdir docs` followed by `touch docs/note.txt` (or `type nul > docs\note.txt` on Windows).
