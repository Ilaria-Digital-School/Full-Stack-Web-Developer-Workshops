# Create your Markdown notes file and version it

Theoretical Recap This workshop builds on your recent lessons on developer notes, Markdown, debugging, and searching for answers. You will solidify these skills by creating a practical, version-controlled system for your learning. Let's recap the core concepts. Markdown is a lightweight markup language using plain text formatting syntax. Its purpose is to be readable as-is and convertible to valid HTML. Documents use a .md or .markdown file extension. It is the standard for documentation, README files, and notes in development. A strong mental model positions Markdown notes as a centralized, living reference you build and refine through documentation, troubleshooting, and research. Each project or topic should link to error logs, solution steps, and helpful resources. Version control, like Git, then tracks this file's evolution, creating a reliable history of your problem-solving journey. Common mistakes include inconsistent structure, where notes become messy and unsearchable. Another is neglecting to version notes, losing the ability to revert or see past insights. A final pitfall is not using Markdown's formatting features like code blocks, which reduces clarity. For example, a note on a debugging session might contain: 1) The exact error code, 2) The three commands you ran to isolate the issue, and 3) The final, successful fix, formatted as a code snippet. Workshop Brief and Preparation Your goal in this workshop is to create a comprehensive Markdown notes file and place it under version control.
